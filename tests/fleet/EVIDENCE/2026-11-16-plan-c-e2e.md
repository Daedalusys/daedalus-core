```bash
ssh Masterwet_Server 'cat > ~/daedalus-e2e/run-g4.sh' <<'REMOTE'

export DAEDALUS_FLEET_DIR=$(mktemp -d)

export DAEDALUS_FLEET_GUEST_ALIASES="ubuntu24-a=vmu debian12-a=vmd rhel9-a=vmr legacy-no-snapshot=vmc"
bash tests/fleet/plan-c-e2e.sh --hosts \
  ubuntu24-a=localhost:9471 debian12-a=localhost:9472 \
  rhel9-a=localhost:9475 legacy-no-snapshot=localhost:9473
REMOTE
```

三个 env 缺一不可(缺哪个的失败长什么样见 §4):

- `DAEDALUS_POLICY_PATH` —— 不给则 `policy` fail-closed 拒启动;
- `DAEDALUS_FLEET_GUEST_ALIASES` —— 夹具机器名 → ssh 别名的映射,驱动要靠它进目标机做基线清理;
- `DAEDALUS_FLEET_DIR` —— 每次矩阵用独立 fleet 根:node_id 每次 Register 都轮换,复用同一个
  注册表会把上一轮僵尸行算进"节点数"断言。

## 2. 结论:G4 的四条主张,真机上逐条成立

### 2.1 口径 C:声明版本与实际不符 → 如实 PERSISTENT(整批 dirty)

```
  plan submit plan-version-mismatch.json: {"plan_id":"0badc0de5eed0001","status":"dirty","max_risk":"low",...,"results":[{"node_id":"ubuntu24-a-b18bf34c","intent_kind":"package","outcome":"persistent","result":"persistent_failure","tx_id":"","message":"apply failed, no rollback point for kind=package: exec: persistent failure: version mismatch: declared=9.9.9 actual=1.24.0-2ubuntu7.19"}],"recovery":[]}
  ok   - 口径 C 腿 → status=dirty(单台持久失败)
  ok   - 口径 C 腿 → 结果 PERSISTENT_FAILURE(控制面词表 persistent_failure)
  ok   - 口径 C 腿 → 文案含 declared=9.9.9 与 actual=
  ok   - 目标机实况:ubuntu24-a 的 nginx 版本 = 1.24.0-2ubuntu7.19
  ok   - agent 审计链留痕(原文):{"args": {"kind": "package", "target": "nginx"}, "entry_hash": "2593c098cd841155ca1084b0368dd522234d22aef1ffd1fd2c854cd3120cebb9", "identity": "0badc0de5eed0001/ubuntu24-a-b18bf34c/0", "outcome": "apply_failed: exec: persistent failure: version mismatch: declared=9.9.9 actual=1.24.0-2ubuntu7.19 (no rollback point for kind=package)", "timestamp": "2026-11-16T10:31:34.641117+00:00", "tool": "apply_intent.failure"}
```

要点:**声明的版本没被满足 → 如实报持久失败,而不是"装上了就算成功"**;审计链留痕带
`declared`/`actual` 两头,可事后复核。

### 2.2 低危腿:三台各自落地,批序正确

```
  ok   - low.json → status=complete
  ok   - low.json → all(.results[]; .tx_id != "")
  plan submit low.json: {"status":"complete","max_risk":"low","batches":[{"index":0,"node_ids":["ubuntu24-a-b18bf34c","debian12-a-fd1f358f"]},{"index":1,"node_ids":["rhel9-a-38f8ee7c"]}],...}
```

### 2.3 高危腿:下发前就拒

```
  ok   - high.json → status=dirty
  ok   - high.json → any(.results[]; (.message | ascii_downcase | contains("snapshot")))
```

### 2.4 人审恢复(多选项三选一,本脚本演练 `--skip`)

```
  ok   - plan advance --skip legacy-no-snapshot-99add271
  ok   - 被 skip 的节点已从待跑批次摘掉
  ok   - 剩余批次只剩另一台(不是"本来就没有"的空过)
  ok   - 被 skip 的结果标成人已接受
```

### 2.5 混合腿(agent 落地 + atomic 停手)—— G4 的核心形态

```
  ok   - 混合腿 → status=dirty
  ok   - 混合腿 → 两个子批、agent 那台在第一批
  ok   - 混合腿 → agent 那台真落地:成功 + 非空 tx_id(注册形态 agent)
  ok   - 混合腿 → atomic 那台停手:持久失败、无 tx_id、注册形态 atomic
  ok   - 混合腿 → 拒绝文案点名「无回滚点」
  ok   - 混合腿 → 只有这两条结果(没有第三个节点被动过)
  ok   - atomic 那台 0 次 RPC:agent 审计链 15 → 15 行(未增长)
  ok   - atomic 那台审计链里没有本 Plan(5eeded1a2b3c4d5e)的任何一行(0)
  ok   - agent 那台实况:nginx 已装 = 1.24.0-2ubuntu7.19
  ok   - agent 那台审计链里有这次 apply 的记录(5eeded1a2b3c4d5e 共 6 行,身份即 intent_id)
```

逐字对照 spec G4:"Plan 落地后任何机器**不自动滚后续批**;半成功整批暂停"——
混合腿里 agent 那台真落地、atomic 那台被拒且**审计链零增长**(一个 RPC 都没到那台),
后续批没有自动继续。**"后续批排队"由人审恢复那条腿证明**(`plan advance --skip` 后
被摘掉的节点从待跑批次里消失,剩下的批次不是空过)。

## 4. 本轮之前的三次失败(如实记:三次都是**驱动侧配置**问题,不是产品缺陷)

| 轮 | 症状 | 真因 | 处置 |
| --- | --- | --- | --- |
| ① | `guest_exec: ubuntu24-a 没有 ssh 别名(设 DAEDALUS_FLEET_GUEST_ALIASES)` → 混合腿基线清理失败 | 驱动要**夹具机器名 → ssh 别名**的映射,只给 `--hosts` 的 `host:port` 不够 | 补 `DAEDALUS_FLEET_GUEST_ALIASES` |
| ② | 口径 C 腿 3 条 FAIL:plan 报 `status=complete` / `outcome=success`,而断言要 `dirty` / `persistent_failure` | guest 上装的是 **11-14 的 agent 包**(`3193c2b`),**不含**口径 C 的版本核对(`verifyPackageVersion` 由 `c909821` 引入,晚于 `3193c2b`)。`plan-c-e2e.sh` 自己不装 agent,沿用上一轮 `agent-e2e.sh` 装上的版本 → 换 tarball 不生效 | 先给四台装上含 `c909821` 的 agent(`b63c03c`),再跑 |
| ③ | `节点数 = 4` FAIL(实际 8) | 复用了同一个 fleet 根,上一轮注册的僵尸 node_id 行还在注册表里 | 每轮用独立 `DAEDALUS_FLEET_DIR` |

> ②那一轮最值得记:驱动的"口径 C 腿"**当时是假绿的反面** —— 断言在红,而产品其实是对的,
> 是被测端版本太老。**这说明"探针红了"第一反应该是查被测端版本,而不是改产品**。
> 同理,`2026-11-15-plan-c-e2e.md` 里写的"被控端 3193c2b"与那一轮 34/0 的口径 C 结果
> **对不上**(该包不含版本核对),那一轮实际用的被控端应当是含 `c909821` 的构建;
> 本文件不改那份历史记录,只在这里把矛盾标出来。
