## 7. 与期望不符之处

**照实写**。每条格式:`现象 → 期望 → 实际 → 影响 → issue 号`。

### D1(已在 #133 修复):高危准入对 agent 节点只看 kind,拒得比执行器还多

- **现象**(②③ 轮):高危 `package` 在 `RSYNC_TARGET` 的节点上也被拒。
- **根因**:控制面 `intentHasRollbackPoint` 对 agent 节点返回
  `objectmodel.HasRollbackPoint(kind)`(恒等于 `kind == file`);而 agent 的
  `apply_intent.go` 本来就接收 `package` / `service`(靠 dnf history / apt before-state
  的回滚凭据),同一份契约两种口径。
- **修法**:口径定为 **A(镜像执行侧)** —— SDK 增 `HasRollbackHandle` /
  `AdmitsHighRisk`,控制面与 agent 共用一张表(`daedalus-sdk#55` / `daedalus-core#133` /
  `daedalus-agent#28`)。第④轮即按新口径跑。
- **副作用**:RF1 的落点从"节点没有快照"变成"kind 没有还原手段",
  夹具相应换成 `container`(见 §5)。
- **issue 号**:`daedalus-core#130`。

### D2(未修):拒绝文案把常量 `SNAPSHOT_CAPABILITY_NONE` 当成节点能力值打印

- **现象**:同一句式 `snapshot capability=SNAPSHOT_CAPABILITY_NONE/<实际值>`,
  前一段是硬编码常量。第④轮里 `e2e-u24-f2295738` 那条仍写着
  `NONE/"SNAPSHOT_CAPABILITY_RSYNC_TARGET"`。
- **影响**:诊断误导(让人以为节点没有回滚点);判定结果不受影响。
- **issue 号**:`daedalus-core#131`。

### D3(未修):开发态策略文件回溯只认目录名 `daedalus-core`

- **现象**:仓副本目录改名即 `policy: 未找到 policy.toml`,控制面 fail-closed 拒跑(§1 第①轮)。
- **现状**:靶场显式给 `DAEDALUS_POLICY_PATH` 绕过;刻意不用
  `DAEDALUS_POLICY_MODE=development`(要验的是生产策略)。
- **issue 号**:`daedalus-sdk#54`。

### D4(未修,需定口径):`package.set` 接受 `spec.version` 但从不落实

- **现象**:夹具声明 `spec.version: 1.24.0`,三台全 `success`,实际是
  `1.24.0-2ubuntu7.19` / `1.22.1-9+deb12u10` / `1.20.1-32.el9_9.1`。
- **根因**:`daedalus-agent/internal/exec/package.go:45-49` 的 `packageSpec.Version`
  只为避开 `DisallowUnknownFields` 而声明,不参与执行;`expected_diff` 无人校验。
- **影响**:`package.set` 的语义实际是"包在/不在";§4 已按此收窄口径。
- **issue 号**:`daedalus-agent#27`。

### D5(新增):`container` 高危被拒时,文案仍在讲 `snapshot`

- **现象**:拒绝原因已经不是"节点没有快照",文案仍是
  `无回滚点(snapshot capability=…)`。
- **期望**:文案应说明"该 kind 既无内建回滚点、执行器也不产凭据"。
- **影响**:与 D2 同源(同一处 `fmt.Sprintf`),合并修一次即可。
- **issue 号**:并入 `daedalus-core#131`。

### 附:已核实不算缺陷的两点

- **`node_id` 的进程态**:四轮拿到的 `node_id` 完全相同(`e2e-u24-f2295738` 等),
  说明 agent 进程未重启时后缀稳定;agent 一重启后缀会变,登记表旧行随即失效
  (`Registry.Get` 报"未注册")。本轮登记与提交同会话完成,未踩到。**风险登记,不是缺陷**。
- **台数与命名**:`node list` 恰 4 台;`vmc` 只登记一次(同一 guest 二次登记会因
  `node_id` 去重而互相覆盖,故 `rhel9-a` 用 `vmr` 而不是 `vmc`)。
